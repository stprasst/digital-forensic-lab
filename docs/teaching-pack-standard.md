# Teaching Pack Standard

This document defines the standard structure and quality bar for every lab's teaching pack in this repository. Follow it when building materials for Labs 02-07 so the series stays consistent for students, instructors, and teaching assistants.

## Per-lab pack contents

Every lab ships, in `Lab XX/`:

| Item | File naming | Audience |
| --- | --- | --- |
| Lab README | `README.md` — upstream theory + a "Course additions" tail | students |
| Main deck | `Lab XX Presentation - <Topic>.pptx` (+ PDF) | students |
| Deep-dive deck | `Lab XX Deep Dive - <focus>.pptx` (+ PDF) | students |
| Working paper | `Lab XX Working Paper - <Topic>.docx` (+ PDF) | students |
| Answer key | `Lab XX Working Paper - Answer Key.docx` (+ PDF) | instructor only |
| Instructor notes | `instructor/NOTES.md` (+ reference images) | instructor only |
| Exercise files | `files/` (flat — no `extra/` subfolder) | students |
| Asset generator | `instructor/tools/` (scripts that generate challenge files) | instructor only |

## Design system (all decks and documents)

- Palette: navy `0F2233` (dark slides), teal `1B6B7A` primary, cyan `37DCF2` accent, off-white `F7FAFC` content background. One accent family for the whole series — students recognize the course at a glance.
- Fonts: Segoe UI (sans) + Consolas (monospace) — ship with Windows/Office, no substitution surprises.
- Deck motif: dark terminal blocks with three window dots (cyan commands, pale-mint output, gray comments, amber highlights).
- Documents: Calibri body 11pt, teal H1/H2, teal-header tables, gray monospace command lines, bordered answer boxes, checkbox steps.
- Decks: 13.33 × 7.5 in (`LAYOUT_WIDE`); documents: A4, 1.3 line spacing.

## Working paper — mandatory sections

1. **Overview** — objectives, environment & files table, what to submit.
2. **1.4 Pre-Lab Check** — 5 short questions answered BEFORE the session (worth 10 points). Forces preparation; graded.
3. **Theory primer** — condensed theory with reference tables (commands, event IDs, ports — whatever the lab needs).
4. **Guided drills** — lettered (3.A, 3.B, and so on) hands-on steps with expected outputs; the guided rehearsal for the challenge.
5. **Challenges** — numbered 4.1, 4.2, 4.3 with a staged hint ladder (3 hints, encourage stopping after each).
6. **Analysis questions** — the original lab questions translated/adapted + 2-3 new scenario questions.
7. **Reflection & self-assessment** — open box + "I can" checklist.
8. **Appendices** — A: command cheat sheet; B: evidence log with the "model exhibit" example (good vs bad evidence); C: hash verification form; D: glossary of every term used.

## Evidence discipline (the course's signature rule)

- Every screenshot/output is an exhibit numbered `B-01, B-02, and so on`, logged in Appendix B.
- "No evidence, no answer" — every factual claim in the working paper must cite an exhibit number.
- Hash before and after analysis (Appendix C); always work on copies, never on `files/` originals.

## Answer key rules

- Instructor only: lives in `instructor/`, which is **gitignored** — never committed or distributed.
- All model answers rendered in RED (#C00000) with a red "INSTRUCTOR COPY" header on every page and a RESTRICTED banner on page 1.
- Contains: marking scheme (100 pts — pre-lab 10, drills 20, challenges 30, questions 25, reflection 10, evidence discipline 5), model answers for every question, challenge flags, reference hashes of the shipped files, and the attack timeline for log challenges.

## Flags and challenges

- Course flag format: `ctf{xxxx}`. Upstream flags keep their original format and are marked as such.
- Worked examples in the Deep Dive deck stop at the FIRST challenge (A): it is solved live as a teaching model; B (a twist on the same skill) and C (a different skill) stay unsolved everywhere students can see.
- Challenge files are generated by a seeded script (`instructor/tools/`) so they can be regenerated byte-identically; the instructor reference (uncorrupted versions, flags) stays in `instructor/`.

## Speaker notes

- Every slide in every deck carries instructor speaker notes (what to emphasize, common student mistakes, interaction prompts, timing).
- Notes are in English, 1-3 sentences, written for a TA who has never taught the session before.

## QA pipeline (mandatory before releasing any file)

1. `postcheck.py` on every generated DOCX — zero errors.
2. Footer field fix (`fix_footer_fields.py`) for page numbers.
3. Render to PDF via LibreOffice, then per-page visual acceptance (automated judge) — all pages must pass.
4. Flag-leak check: the only `ctf{`/`flag{` strings in student-facing files are placeholders or intentionally revealed flags (Challenge A).
5. Commit only student-facing files; `instructor/` stays local (`.gitignore`).

## Naming and git

- Deliverables at `Lab XX/` root; evidence files flat in `Lab XX/files/`.
- Commit messages: `Add Lab XX <thing> (...)` — one logical pack per commit.
- PDF exports accompany every deck/document for easy student distribution.
